# Privacy

IntervAIew is local-first, not offline-only in every provider mode.

- **Mock planning/text mode:** makes no external AI request.
- **DeepSeek planning:** sends resume, job description, role/company, interview settings, language, and question count to DeepSeek only to create the fixed question plan. DeepSeek never receives voice audio or recorded tracks.
- **OpenAI text planning:** sends the same planning material to OpenAI only while creating the fixed plan.
- **OpenAI Realtime voice:** after required explicit consent, sends microphone audio to OpenAI Realtime and receives interviewer audio plus transcription events. Resume and job-description text are not resent to the Realtime session.
- **Fake Realtime tests:** do not request a microphone or contact OpenAI.
- **Transcript Lab:** uses only an explicitly enabled non-production Fake transcript source. It requests no microphone, captures no audio, sends nothing to OpenAI or DeepSeek, keeps interim text only in current page memory, and stores final transcript segments in the local/server SQLite database.
- **Question Boundary Detector:** uses persisted final interviewer transcript segments. Deterministic rules run locally; the bundled Fake Semantic provider is non-production, deterministic, and never accesses the network. Provider raw requests/responses and model reasoning are not logged, returned, or stored.
- **Question Understanding:** uses only active finalized question wording plus revision/provenance. Deterministic rules and the optional non-production Fake Semantic provider run locally without a network request, API key, or charge. Results are bounded structured metadata, never answers, summaries, resume evidence, provider payloads, or reasoning.
- **Uploaded Audio:** stores a user-selected authorized practice file beneath the configured server filesystem root and safe metadata/jobs in SQLite. Upload does not transcribe. A separate explicit action queues local processing. v0.5 includes only a deterministic network-free non-production Fake adapter, so no uploaded audio is sent to OpenAI, DeepSeek, or another external service.
- **Database backups:** contain the same sensitive SQLite content as the source database, including resume, job-description, question, answer, and transcript data. Backup files remain on the local/server filesystem unless an operator deliberately moves them. Backup encryption, compression, and cloud backup are not implemented. Recording and Uploaded Audio bytes are not included, so this is not a complete application backup.

Input transcription may not be word-for-word exact. Only finalized candidate transcription is stored as a voice answer; interim text remains in browser memory. Output transcript is used for live display and never replaces the stored canonical question. Voice transcripts are not used for scoring or evaluation.

Dual-track recording is separately consented, optional, and off by default. When enabled, candidate and interviewer tracks are saved separately. When running locally, SQLite is at `./data/intervaiew.db` and recording files are beneath `./data/recordings` on that machine. When deployed to a remote server, “local storage” means that server's filesystem—not the user's device. Audio is not embedded in TXT/JSON exports and is not uploaded to DeepSeek or third-party storage.

Uploaded practice audio is stored beneath `UPLOADED_AUDIO_PATH` (default `./data/uploaded-audio`), never in SQLite or export. The original filename is retained only as bounded display metadata and cannot select the storage path. One declared role applies to the whole file because v0.5 performs no diarization. Transcription text may be inaccurate and is not used for scoring or suggested answers. Cancellation prevents stale output from committing but cannot guarantee that provider code already running in memory stops immediately.

Deleting an asset removes its file and metadata; deleting an interview removes associated recording files and cascades questions, transcripts, attempts, assets, and action receipts. Protect host filesystem access and follow applicable retention requirements.

Deleting an Uploaded Audio asset uses a durable staged/tombstone cleanup plan so an interrupted database or filesystem operation remains retryable. Successful cleanup removes its bytes and metadata but intentionally does not delete finalized transcript segments already committed to Transcript Lab. Their source foreign key becomes null. Deleting the analysis session removes those transcript segments and uploaded-audio action receipts; a durable cleanup receipt can temporarily outlive that session row until all remaining uploaded bytes are removed.

Deleting a Transcript Lab analysis session cascades its final transcript segments. Refresh discards interim text because interim chunks are never written to SQLite.

Boundary candidates, decisions, finalized questions, action receipts, and source mappings are local/server SQLite data and cascade with the analysis session. Semantic normalization never replaces the stored final transcript wording.

Understanding parent/child metadata and action receipts also cascade with the analysis session. Undo removes a question from active results; merge binds later metadata to the new question revision and supersedes earlier results without rewriting historical provenance.

Operators are responsible for protecting, retaining, moving, and deleting database backup pairs deliberately; retention and deletion are manual. Offline restore requires an explicit operator confirmation that the application and embedded worker are stopped; this confirmation is not automatic process detection. A replacement restore retains a pre-restore safety backup and never deletes it automatically. Handled failures roll back, but sudden process termination, host failure, or power loss can interrupt the multi-file database/WAL/SHM sequence and require manual recovery from retained files.

Configurable retention applies only to validated local SQLite backup artifact pairs in an explicitly selected directory. It never runs automatically and does not delete sessions, transcripts, questions, recordings, Uploaded Audio bytes or jobs, user-created content, unknown files, or recovery residue. Manifest `createdAt` determines age, the newest configured number of valid pairs always remains, and invalid or incomplete artifacts are never deleted. Pre-restore safety backups are outside the default retention directory; an operator must review and explicitly select another directory before applying retention there. Handled cleanup failures can retain non-normal recovery residue for manual inspection, and sudden termination or power loss is not crash-atomic.

Retention command results, operations-status results, and closed-schema maintenance operational events remain local and content-free. They expose bounded health, count, byte-total, duration, outcome, and safe error-code facts only—not paths, filenames, backup names, hashes, credentials, user/session/asset identifiers, timestamps from individual backups, resume/JD/question/answer/transcript content, SQL, audio metadata, provider data, causes, or stacks. Existing backup, validation, and restore human stdout still reports operator-selected safe artifact basenames and integrity metadata; maintenance events do not repeat it. Events are ephemeral stderr output. No telemetry, analytics, metrics export, persistent operational log, log shipping, cloud storage, or external status request is implemented.

Logs contain safe operational codes and identifiers only. They exclude permanent and ephemeral credentials, resume/JD/answer/transcript text, prompts, provider payloads/events, raw audio, SDP, ICE credentials, and absolute paths. Review provider privacy terms before enabling external modes.
